## 1. 分层与依赖规则

> 本章定义三层服务 + 接口层,以及五条由测试守护的规则。函数内的延迟 import 也算依赖。

```
L2 编排(可依赖任何下层)      pipeline  prospect  scheduler  crawl_runner  locate  autopilot  bootstrap  daily  profiles  capabilities
L1 能力模块(只依赖 L0;同层可用公开函数,不成环)
     采集:adapters columns health wechat      处理:extraction money_guard dedup events review verify relations exports benchmark
     关键词/找源:keywords discovery grading query_evolution      更新/输出:followup leads kpi digest coverage
L0 契约与底座(不依赖上层)   need_ctx tasklib prompts llm fetcher archive url_tools simhash reputation settings_service actions notify diagnostics errors
接口层 app/api、CLI、前端      只调用 L1/L2 的公开函数;服务层永远不引用接口层
```

规则(有测试):
1. 任一模块只能 import 同层或更低层;**函数内的延迟 import 也算依赖**。
2. L1 内部无环(DFS 检查)。
3. `app/services` 不得 import `app.api`。
4. 契约层(`need_ctx` / `tasklib` / `prompts` / `url_tools` / `notify`)只依赖底座。
5. 引擎代码不得出现行业字面量(另一守护测试)。

`tasklib` 放在 L0 的原因:它只读任务与参数库文件、只依赖 `config`;`need_ctx` 需要在无会话时按任务文件编译画像,所以编译器必须在契约层。

## 3. 扩展点(加功能不改别人)

> 本章按"要加什么"给出放在哪、怎么登记、谁会自动看到。

| 扩展点 | 怎么加 | 谁会自动看到 |
|---|---|---|
| 新任务 | `config/tasks/<id>.yaml` + `task-setup` | 自动化按状态跑;`/needs`、`/tasks` 列出 |
| 新参数库条目 | `config/library/<kind>/<id>.yaml`(或 `library-extract`) | 任务 `use`;`library-list` |
| 新任务键(task.* → 画像键) | `tasklib.compile_task` 加一条映射 + 02 §1 登记 + 模板注释 | 所有任务 |
| 新画像维度 | `need_ctx.DEFAULTS` 加中性缺省 + 属性;02 §3 登记 | 老画像不写照常跑 |
| 新源适配器 | `adapters.py` 新类,`name` 唯一,注册进 `_REGISTRY` | 种子源、找源、体检、试抓 |
| 新处理阶段 | `pipeline.py` 写 `_stage_x(db, need, ctx, doc, st, result) -> bool` 并登记进 `STAGES` | 画像 `pipeline.stages` 写上名字即可 |
| 新能力 | `capabilities.py` 用 `@register(name, group, doc, params)` 登记 | `GET /capabilities`、`cap-run`、前端 |
| 新报表内核 | `kpi.py` 新函数 + `reports_engine` 新键 + `capabilities` 登记 | 任务声明即启用 |
| 新回访触发方式 | `followup._trigger_hit` 加一个 `when` 分支 | 画像 `followup_triggers` |
| 新通知渠道 | `notify.CHANNELS["名字"] = fn(subject, body, cfg) -> (ok, note)` | `outputs.notify.channels`、能力 `notify.send` |
| 新导出目标 | `exports.run` 加一个 kind 分支 | `outputs.exports[].kind` |
| 新自动运维任务 | `autopilot.TASKS` 加一项 | 首次流程/每日调度 |

## 4. 升级一个模块的操作规范

> 本章是改代码的六步。核心是"只改实现不改契约、只加不改画像键、三道守护 + 全量"。

1. **先看契约**:只改模块内部实现,不改公开函数签名;要改签名就加参数带缺省值(例:`ctx=None`)。
2. **只加不改画像键**:新参数进 `DEFAULTS` 给中性缺省;旧画像与旧任务不改也能跑;新任务键也只加映射。
3. **跑三道守护**:`pytest tests/test_module_boundaries.py tests/test_platform_generalization.py tests/test_demand_matrix.py`——依赖方向、行业字面量、跨任务行为三样都没变才算安全。
4. **再跑全量**:`pytest -q`。
5. **独立验证一个能力**:`python -m app.cli cap-run <name> --need <id> --params '{...}'`,不必起整条流水线;任务层面用 `task-compile` 看编译结果是否受影响。
6. **只动前端**:前端只认 `/needs/{id}/ui` 与角色键,后端字段变了前端不用改。

## 5. 解耦记录

> 本章记录为达到分层规则做过的解耦,便于理解某些函数为什么在那个模块。

| 原耦合 | 处理 |
|---|---|
| `health → app.api.routes.test_fetch_source` | 试抓逻辑下沉为 `health.probe_source`,接口层只包一层 |
| `discovery → pipeline._is_subject_like` | 主体名判定移到 `url_tools.is_subject_like` |
| `digest → daily.deliver_email` | 邮件推送下沉为底座 `notify.deliver_email`;`daily` 转发旧名 |
| `need_ctx → extraction / keywords`、`llm → extraction` | Schema 加载放进契约层 `need_ctx.load_schema_file`;找源配方回退改由 `keywords.search_queries_for / recipes_for` 提供 |
| `keywords → columns.reset_terms_cache` | 栏目相关词缓存键带关键词版本,自然失效 |
| `query_evolution ↔ prospect` 互相引用 | `query_evolution` 改读 `keywords.recipes_for` |
| `need_ctx → tasklib`(v1.5) | 不是解耦而是归层:`tasklib` 归入 L0,`need_ctx` 才能在无会话时按任务文件编译 |

## 6. 分层升级检查清单

> 本章按层给出升级前确认与升级后必跑,与 03 §2 各层的质量要求对应。

| 层 | 升级前确认 | 升级后必跑 |
|---|---|---|
| 配置层(参数库/任务/画像) | 新键有中性缺省、模板同步、02 登记;改条目前看 `used_by` | `test_task_mode`、`test_platform_generalization`、`test_scenarios`、`test_demand_matrix` |
| 契约层 | 公开属性签名不变;不引用能力层;编译映射只加不改 | `test_module_boundaries::test_contract_layer_only_depends_on_itself` + `test_task_mode` + 全量 |
| 底座层 | 降级链仍在(渲染→httpx,存档 L-A→L-D);离线可跑 | 该模块单测 + `test_llm_compat` + 全量 |
| 能力层 | 只改实现不改签名;新参数带缺省;无同层环 | `test_module_boundaries` + 该能力用例 + 跨任务用例 |
| 编排层 | 幂等、可取消、状态落库、单步失败不拦;只跑可跑任务 | `test_autopilot_grading`、`test_bootstrap`、`test_crawl_job`、`test_parallel_crawl` |
| 接口层 | 角色要求明确、need_id 缺省、无行业字面量 | 字面量扫描 + `test_task_mode::test_task_api_and_cli` + 双需求 HTTP 冒烟 |
| 界面层 | 只认角色与 UI 定义 | 手工切换两个任务各看一遍页签/列表/详情/日报 |
| 数据层 | 只加列不改列;新表带 need_id | 全量 |
