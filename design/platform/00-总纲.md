## 1. 平台使命:围绕"想要的信息"做五件事

> 本章说平台的"为什么":唯一的主线是针对一个信息需求把信息**找得快、找得全、确认真实、整理得好用、分类存到本地**。
> 通知、导出、日报这些是把结果"送出去"的组件,不是主线。本章给出五个目标各自的定义、实现手段与量化方式。

| 目标 | 一句话定义 | 平台靠什么做到 | 怎么量化(评分卡/看板) |
|---|---|---|---|
| **找得快** | 信息一公开,尽快进库 | 任务节奏(cadence)反推分级抓取间隔、官方 JSON 接口直采、搜索引擎定题检索、公众号/平台号通道、翻页早停、时效窗口 | 披露→入库中位时延;引擎/源体检可用率 |
| **找得全** | 该有的都有,不漏 | 任务的范围限定 scope → 关键词自动生成与进化、六通道源发现与主动找源、覆盖度盘点(缺哪块找哪块)、根域源栏目定位、对标基准漏报率 | 覆盖度(维度有覆盖比例)、候选渠道增长、漏报率 |
| **真实可信** | 每条都能说清"从哪来、可不可信" | 来源可信度分级 + 发布主体信誉名录、真实性验证(官方域/正文哈希/标题一致/密级标记)、断言三态(声称/估算/确认)与发布红线、可追溯校验、再核查内容变化 | 可追溯率、验证状态分布、守卫违规率 |
| **好用可用** | 结构化、干净、无重复、能直接用 | Schema 抽取(或轻量抽取)+ 任务规则、三层去重(URL/同稿/记录)、范畴闸门、完备度评分、复核双签、回访补全滞后字段、记录关系谱系(废止/替代/修订/依据) | 完备度均分、重复率、Schema 校验通过率、关键列填充率 |
| **分类存本地** | 按任务/维度/等级/时间落成可直接翻的本地资料库 | 当刻存档(原文/图片/附件/截图,哈希校验)、角色化查询列、本地资料库导出(JSON + Markdown + 快照路径,按路径模板分目录)、数据库主存储 | 存档覆盖率、存档抽检通过率、分类分布 |

五个目标对应质量评分卡的四维:找得全→完整性,真实可信→准确性,好用可用→一致性,找得快→时效性;
"分类存本地"是所有结果的落点,由存档覆盖率单独看。

**合规底线(所有任务共同遵守)**:只采公开渠道;泄露类站点只登记元数据与截图、不下载不存样本;含密级/内部标记的文档只登记不入库正文;
所有产出仅供内部使用,对外引用须经法务;任何输出不得贬损任何主体。

## 2. 运行单位:任务

> 本章说平台的"怎么用":平台以**任务**为运行单位。每新建一个任务,就规定这个任务要干的事——采集什么信息、多久采一次、
> 用什么参数去采、判、存、送。这些参数**为这个任务服务**;其中有共性的参数,泛化成**参数库**里的备选条目留存下来,
> 以备其它任务直接复用。本章给出任务的定义、参数的三个来源、参数库的意义与任务的生命周期;细节见 01。

### 2.1 任务是什么

一个任务 = 一份任务文件(`config/tasks/<id>.yaml`),回答四个问题:

| 问题 | 任务里对应的部分 | 例子(江苏网络安全招标监测) |
|---|---|---|
| **干什么** | `task.name / purpose`、范围 `scope`、粗筛目标 `quality.screen.goal` | 发现江苏省内网络安全类项目的招标/中标公告,跟踪中标人与金额 |
| **多久一次** | `task.schedule`(mode / cadence / time_window_days / time_filters / start / end) | 持续监测,小时级,只采近 30 天 |
| **用什么参数** | `use:`(引用参数库条目)+ `overrides:`(本任务特有) | 江苏地域词 + 网络安全行业词 + 采购公告文种 + 招标记录形态 + 只认官方 + 本地资料库 |
| **现在什么状态** | `task.status`(draft / active / paused / finished) | active |

任务文件经**编译**得到一份完整的画像(引擎契约),引擎只认画像、不认任务;因此新建任务不改任何代码。

### 2.2 任务参数的三个来源

```
        参数库(config/library/<kind>/<id>.yaml)         ← 共性参数:地域词、行业词、文种、记录形态、可信度策略、节奏、输出…
              │ use(按序深合并)
              ▼
        任务文件(config/tasks/<id>.yaml)                ← 本任务特有:目标、状态、节奏、粗筛目标、合规声明、主体名单…
              │ overrides(再合并)+ task.* 映射
              ▼
        画像(need_profile.config,引擎契约)             ← 编译产物;缺的键由平台中性缺省补齐(need_ctx.DEFAULTS)
```

三者的分工:**参数库放"别的任务也会用的"**,**任务放"只有这个任务才有的"**,**平台缺省放"不写也合理的"**。
一个任务通常只有十几行元信息 + 几个 `use` + 少量 overrides;画像有几十个键,由编译器生成。

### 2.3 参数库为什么存在

同一类参数会在多个任务里反复出现:江苏的地市别名、医疗行业的同义词、"政策文档"这种记录形态(Schema + 角色 + 去重键 + 报表口径 + 界面)、
"只认官方来源才能确认"的可信度策略、"小时级 · 近 30 天"的节奏套餐、"发布即落本地资料库"的输出。把它们**从任务里提炼出来存成条目**,
下一个任务直接 `use`,好处有三:写得少(任务只写特有部分)、改一处处处生效(条目改动就是新版本,`library-list` 能看到被谁引用)、
沉淀经验(验证过有效的词表和规则不会随任务结束而丢失)。

### 2.4 任务的生命周期

| 阶段 | 做什么 | 入口 |
|---|---|---|
| 新建 | 复制模板 → 填元信息与节奏 → `use` 现成条目 → 只写特有的 overrides | `config/tasks/task.template.yaml` |
| 编译/校验 | 看编译结果是否符合预期;引用不存在的条目直接报错 | `cli task-compile <id>`、`GET /tasks/{id}/compile` |
| 装载 | 注册画像 + 载词表 + 关键词自动生成 + 种子源;幂等 | `cli task-setup <id>`、`POST /tasks/{id}/setup` |
| 运行 | 状态 active 且在有效期内的任务进入每日采集、自动运维、日报、导出、回访再核查 | 自动 |
| 暂停/恢复/结束 | 用状态而不是删文件;数据与资料库保留 | `PUT /tasks/{id}/status` |
| 提炼 | 把验证有效的一段(如地域词)存进参数库,供下个任务复用 | `cli library-extract`、`POST /library/extract` |

## 3. 信息获取闭环(主线)

> 本章说一个任务装载之后,平台按什么顺序把信息找到、处理、存好。闭环的每一步都是独立能力(`capabilities` 注册表),
> 按任务的 `pipeline.stages` 组合;每一步只从任务编译出的画像(`NeedContext`)取参。

```
        ┌──────── 任务的范围限定 scope(地域/行业/主题/主体/文种/时间窗)────────┐
        │                                                                       │
  关键词生成/进化 ──→ 定题检索 ──┐                                              │
  源发现/主动找源 ──→ 源库 ──────┼──→ 采集(抓取/渲染/存档/去重) ──→ 验证(真实性)    │
  覆盖度盘点(缺哪块找哪块)──┘            │                                       │
                                          ▼                                      │
                       粗筛 → 抽取 → 范畴闸门 → 记录去重 → 草稿 → 复核/发布      │
                                          │                                      │
                          回访补全 ← 记录 ─┴─→ 关系谱系 → 本地资料库(分类存储)    │
                                          │                                      │
                          评分卡/覆盖度 ───┴───────────── 反馈:找源词、缺口 ──────┘
```

| 环节 | 对应目标 | 任务里决定它行为的参数(见 02) |
|---|---|---|
| 范围限定 → 关键词 → 找源 → 覆盖度 | 找得全 | `scope.*`、`keywords.*`、`coverage.*`、`sources.discovery_file` |
| 采集(节奏/时效窗/适配器) | 找得快 | `task.schedule`、源 `tier`、`sources.seed_file` |
| 验证 / 可信度 / 三态 / 红线 | 真实可信 | `sources.credibility_levels`、`sources.verification`、`quality.assertions` |
| 粗筛 / 抽取 / 闸门 / 去重 / 回访 / 关系 | 好用可用 | `quality.screen`、`record_schemas`、`pipeline.extract_mode`、`record.dedup`、`update.*` |
| 存档 / 本地资料库 / 数据库 | 分类存本地 | `outputs.exports[]`、设置 `archive_*` |

## 4. 主线之外的功能组件(可插拔,不影响主线)

> 本章列出不属于主线、但任务可以按需启用的组件。它们都有明确的插件点,新增渠道或目标只登记一个函数,不改引擎。

| 组件 | 作用 | 插件点 | 任务里怎么启用 |
|---|---|---|---|
| **通知组件** `notify` | 把日报/告警送到人 | `notify.CHANNELS`:email / feishu / webhook(钉钉、企微、自建同一入口) | `outputs.notify.channels`;未声明用设置里配齐的渠道;参数库条目 `outputs.notify.all_configured` |
| **导出组件** `exports` | 把记录送到本地目录或别的系统 | `exports.run` 的 kind:`local_library` / `feishu_bitable` | `outputs.exports[]`;参数库条目 `outputs.local_library` |
| 日报 `digest` | 每日汇总 | — | `outputs.digest`;用通知组件送出 |
| 线索引擎 `leads` | 记录 → 商机 | — | `outputs.leads_engine.enabled`(首个实例专用,其它任务默认关) |
| 报表内核 `kpi` | 交叉表/金额/状态/缺字段/评分卡 | — | `outputs.reports_engine`;口径全由任务声明 |

## 5. 角色与使用路径(谁在什么时候用什么)

> 本章按角色说各自的日常事项、用到的功能(04 的编号)与效果最大化的习惯。任务模式下,"需求负责人"就是新建任务的人。

| 角色 | 日常要做的事 | 用哪些功能(04 编号) | 效果最大化的习惯 |
|---|---|---|---|
| 需求负责人(建任务的人) | 定义"要什么":新建任务、选参数库条目、写范围与粗筛目标 | T1–T4 任务与参数库、B1 scope、D2 抽取模式、C1 可信度、D8 回访触发 | 先用现成条目拼 + 轻量模式 + 一键演示跑通,再加 Schema;每个范围值给同义词 |
| 运营 | 让源库健康、关键词有效;维护参数库 | A2 配源、B2 关键词、B5/B6 找源与自检、B4 候选池、G3/G4 自动运维与体检、T3 提炼 | 每周看一次候选池与"找源完成"结论;验证有效的词表提炼进库 |
| 分析员 | 看记录、报表、覆盖度、评分卡 | D10 列表/详情、F4 报表、B8 覆盖度、E3 本地资料库 | 从仪表盘卡片下钻;覆盖空白就是下周的找源方向 |
| 复核员 | 复核发布、合并重复、处理待定 | C5 复核台、D7 待定队列、C4 三态字段 | 先看来源等级与三态状态,再看正文;红线拦下的补来源而不是硬发 |
| 管理员 | 设置、账号、渠道、导出目标;任务装载与暂停 | G6 设置页、F1 通知渠道、F5/E3 导出、G8 审计、T2 装载 | 缺省值尽量不改;改 LLM 后点"测试连通";暂停用状态不删任务 |
| 开发者 | 扩展能力、渠道、适配器、参数库平台级条目 | G5 能力注册表、07 扩展点、G9 守护测试 | 新东西只登记不改引擎;升级前跑三道守护 |
| 自动化 | 每日采集、自动运维、日报、导出、再核查 | A1/A8、G3、F2、E3、C7 | 只跑 active 且在有效期内的任务;时间预算而不是条数上限;失败不拦后续 |

## 7. 主线闭环状态

> 本章记录五目标当前做到哪一步,哪些还要在真实环境里校准。版本增量的明细见 06。

| 目标 | 已闭环(v1.5) | 仍需真实环境校准 |
|---|---|---|
| 找得快 | 任务节奏 → 分级调度、json_api(GET/POST)、编码探测、时效窗 | 引擎可用率与时延要在真实网络上看 |
| 找得全 | 范围→关键词→找源→覆盖度→对标漏报率(进评分卡) | 关键词模型扩展、切题率与候选阈值 |
| 真实可信 | 分级/名录/验证阶段/三态/红线/可追溯/再核查接回访/验证状态可见 | 官方域名录按任务扩充 |
| 好用可用 | 抽取/去重/闸门/完备度/回访/关系谱系/评分卡进仪表盘 | 条款级二次抽取、关系可视化(P1) |
| 分类存本地 | 数据库 + 存档 + 发布即落资料库 + 每日导出任务 | — |
| 任务模式 | 任务文件、参数库(18 条)、编译/装载/状态门控、提炼、五个任务样板 | 参数库页面化(P1) |
| 组件 | 通知渠道注册表(紧急动作即时通知)、导出目标注册 | 按需接新渠道 |
