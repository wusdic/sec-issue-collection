# 通用数据采集平台 · 需求泛化模型与决策表(v1.2)

> 06 用了"医疗政策 / 招标中标 / 企业定向 / 省市文件"四个例子。例子只是例子;本文把**需求空间**抽象成
> 正交轴,任何"采集某一类公开信息"的需求都是这些轴上的一个取值组合,画像只需按轴填值。
> 并用**生成式验证**(`tests/test_demand_matrix.py`:程序按轴组合生成画像、装载、跑链路)证明平台对
> 没见过的组合同样成立,而不只是对手写的几个例子成立。

## 1. 需求空间的六根轴

| 轴 | 问题 | 取值 | 画像里的落点 |
|---|---|---|---|
| **W 对象**(what) | 记录的是什么 | 事件型 / 文档型 / 对象型 / 观测型 | `record_schemas[].archetype`、`record.field_roles`、`record.dedup`、`record.record_types` |
| **S 范围**(which) | 要哪一片 | 地域 × 行业 × 主题 × 主体名单 × 文种 × 时间窗;每维可"必须提及" | `scope.*`、`scope.require_mention`、`scope.time_window_days` |
| **F 来源**(where) | 从哪来 | 官方站栏目 / 平台号 / 搜索引擎 / RSS / 聚合站 / 名录;地域偏好 | `sources.seed_file`、`sources.discovery_file`(可省→按 scope 生成)、`sources.region_policy`、`column_discovery` |
| **D 深度**(how deep) | 抽多细、多严 | 轻量(标题/摘要/主体/分类)/ Schema;断言三态开/关;确认等级 | `pipeline.extract_mode`、`pipeline.light_fields`、`quality.assertions`、`sources.credibility_levels.confirm_allowed` |
| **L 生命周期**(how it changes) | 入库后还变不变 | 一次性 / 状态跃迁(文号)/ 持续补全(回访)/ 持续跟踪(名单) | `update.followup_triggers`、`followup_schedule`、`watch_kinds`、`record.dedup.window_days` |
| **O 输出**(for what) | 给谁用 | 日报 / 交叉表 / 金额汇总(三态或数值)/ 状态计数 / 缺字段清单 / 线索 | `outputs.digest`、`reports_engine.*`、`leads_engine.enabled` |

关键词生成不是一根轴,是 **S 轴的派生物**:词组 = scope 五维 + 静态词组 + 监控名单;配方 = 锚点(主体/地域/行业)× 对象(主题/事件/动作/文种)。

## 2. 决策表:需求特征 → 画像怎么填

| 需求特征 | 填什么 |
|---|---|
| "只要 X 省/市的" | `scope.regions: [{value: X省, terms: [X, 市名…]}]`,`require_mention: [regions]`;找源词自动带地域 |
| "只要 X 行业的" | `scope.industries`(含同义:医疗/医院/医保),`require_mention: [industries]`;`coverage.scope_kind: topics` 让覆盖度按主题看 |
| "只要某几家企业/某厅局的" | `scope.entities: [{value: 正式名, aliases: […]}]`,`require_mention: [entities]`;运行中可继续往监控名单(WatchTarget)加 |
| "某类文件(通知/办法/公告)" | `scope.doc_types`;文档型;`record.dedup.subject_roles: [subject_key(文号), subject+title]`,`window_days` 放大 |
| "招标/中标这类有编号、有金额的对象" | 对象型;`subject_key` = 编号;`amount_sum.kind: plain`;`followup_triggers` 盯"未公布中标人";`missing_field: winner` |
| "事件,后续会有罚款/判决/整改" | 事件型;`assertions.tristate_fields` + `confirm_allowed`;`followup_triggers status_in [仅声称…]`;线索引擎按需开 |
| "先看个大概,不要 50 个字段" | `pipeline.extract_mode: light`,需要的字段用 `light_fields` 追加,`field_roles` 只改要改的角色 |
| "不需要 LLM 抽取,只要收集标题" | `pipeline.stages: [screen, draft]`(草稿=标题+摘要) |
| "没有词表/关键词/种子/配方文件" | 都省略:关键词按 scope 生成、找源配方按 scope 生成、覆盖度取值来自 scope、Schema 用轻量 |
| "要自动扩关键词" | `keywords.expand_with_llm: true`(或页面"生成并用模型扩展"),或运行中 `query_evolution` 从相关标题挖词 |
| "同一类需求换个地域/行业再来一份" | 复制画像,只改 `need.id/name` 与 `scope`,其余不动 |

## 3. 例子回填(七类举例都是组合)

| 例子 | W | S | D | L | O |
|---|---|---|---|---|---|
| 网络安全事件库 | 事件型 | 行业=全国各行业 | Schema + 三态 | 回访补全 | 线索/报表/日报 |
| 安全法规 | 文档型 | 主题=安全法规 | Schema(政策) | 文号状态跃迁 | 日报 |
| 医疗行业最新政策 | 文档型 | 行业=医疗(必须提及)+ 主题 | Schema(复用政策) | 生效日回访 | 日报 |
| 某类招标/中标 | 对象型 | 地域=江苏(必须提及)+ 行业 + 文种 | Schema(招标)+ 数值金额 | 待公布中标人 | 金额汇总/缺字段 |
| 某省市地域某类文件 | 文档型 | 地域(必须提及)+ 主题 + 文种 | 轻量 | — | 日报 |
| 某行业/厅局的政策要求 | 文档型 | 主体=厅局(必须提及)+ 行业 | Schema 或 轻量 | 文号 | 日报 |
| 某企业定向信息 | 观测型 | 主体名单(必须提及)+ 主题 | 轻量 + 追加倾向字段 | 名单持续 | 日报 |

## 5. 已知的轴外需求(不承诺、说清楚)
- 非中文/境外源为主的需求:适配器与地域策略可配,但 Mock/提示词默认中文语境;需要一轮真实模型验证。
- 需要登录/付费接口的来源:平台只做公开渠道(合规边界),不在范围内。
- 站点专用字段级解析(如政府采购网列表字段):走通用列表模板,需要精细字段时加适配器。
