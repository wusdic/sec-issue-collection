# 通用数据采集平台 · 参数手册(v2.0)

> 本文回答"**一个任务能设置哪些参数、每个参数管什么、不填会怎样**"。所有参数都是为任务服务的:
> 任务级参数写在 `task:` 段;画像键通过 `use`(参数库)或 `overrides`(本任务)进入编译后的画像;没写的键取平台中性缺省。
> 本文是代码契约:每个键给出 路径 / 类型 / 缺省 / 消费方。

## 1. 参数的三个层级

> 本章说明参数按归属分三级,以及任务元信息怎么映射到画像键。归属规则一句话:**别的任务也会用的进参数库,只有这个任务才有的写在任务里,不写也合理的交给平台缺省。**

| 层级 | 落点 | 放什么 | 例 |
|---|---|---|---|
| 任务级 | `config/tasks/<id>.yaml` 的 `task:` | 目标、状态、节奏、预算 | `schedule.cadence: hourly` |
| 参数库级 | `config/library/<kind>/<id>.yaml` 的 `body:` | 共性的画像片段 | `scope.regions` 江苏地市别名 |
| 画像级 | 编译产物 / `overrides:` / 手写画像 | 引擎契约的全部键(§3) | `quality.screen.goal` |

**任务键 → 画像键**(编译时自动映射):

| 任务键 | 画像键 | 说明 |
|---|---|---|
| `task.id / name / owner / priority` | `need.id / name / owner / priority` | 任务即需求 |
| `task.schedule.cadence` hourly/daily/weekly/alert | `need.timeliness_sla` 小时级/日级/周级/告警级 | 分级抓取间隔由 SLA 反推 |
| `task.schedule.time_window_days` | `scope.time_window_days` | 采集时效窗 |
| `task.schedule.time_filters` | `keywords.time_filters` | 检索时间过滤(替换) |
| `task.budget.query_budget_per_source_daily / max_pages_per_query` | `keywords.*` 同名 | 配额 |
| `task.status / schedule.mode / start / end` | 编译产物 `task.*` | 只用于自动化门控,不进引擎参数 |
| `use: [...]` | 各条目 `body` 按序深合并 | 列表追加去重 |
| `overrides` | 与画像同构 | 本任务特有 |

## 2. 任务级参数

> 本章逐项说明 `task:` 段。它们回答"这是哪个任务、跑不跑、多久一次、花多少配额"。

| 键 | 类型 | 必填 | 缺省 | 说明 |
|---|---|---|---|---|
| `task.id` | str | ★ | — | 任务 id = 需求 id;记录号、源、词表、回访、报表全部按它隔离 |
| `task.name` | str | ★ | = id | 界面标题、提示词里的需求名、日报标题的来源 |
| `task.owner` | str | — | — | 负责人;进 `need.owner` |
| `task.purpose` | str | 建议 | — | 一句话说清要拿到什么、给谁用;写粗筛目标的依据 |
| `task.status` | draft / active / paused / finished | ★ | draft | 自动化只跑 active |
| `task.priority` | A / B / C | — | 参数库或 B | 抓取与查询配额优先级 |
| `task.schedule.mode` | continuous / campaign / once | — | continuous | campaign 看 start/end;once 跑完标 finished |
| `task.schedule.cadence` | hourly / daily / weekly / alert | ★ | 参数库(如 `schedule.daily_365d`) | → `need.timeliness_sla` |
| `task.schedule.time_window_days` | int | — | 参数库或运行时设置 `collect_recency_days` | 早于窗口的历史内容只留薄记录用于去重 |
| `task.schedule.time_filters` | list[str] | — | 参数库或空 | 检索引擎的时间过滤词,如 `近7天` |
| `task.schedule.start / end` | ISO 日期 | — | null | campaign 的有效期 |
| `task.budget.query_budget_per_source_daily` | int | — | 200 | 每源每次查询条数上限 |
| `task.budget.max_pages_per_query` | int | — | 3 | 每个查询最多翻几页 |

## 4. 流水线各阶段消费哪些参数

> 本章把引擎"固定做什么"与"任务决定什么"按阶段对照,方便判断某个效果是改参数还是改代码。记录四型(事件/文档/对象/观测)的引擎差异只体现在两处:第三层去重键与生命周期语义。

| 阶段 | 引擎固定逻辑 | 任务参数 |
|---|---|---|
| ① 源层:种子/发现/找源/定位栏目/体检/定级/自动运维 | 一源多任务;候选池评分与多通道闸门;栏目结构一致性;时间预算护栏;引擎自检与切题率 | C1 种子、C5 名录、B3/B8 找源配方与自检词、B5 栏目提示词、C6 地域策略、C3 定级规则、C4 评分权重 |
| ② 采集层:适配器/渲染/反爬/翻页早停/时效/存档 | 全部平台级;`render=auto`、早停、时效窗口、广采薄存 | `scope.time_window_days`(来自 task.schedule);其余运行时设置 |
| ③ 去重:URL / 文档 SimHash / 记录指纹+语义 | 前两层完全通用;第三层按去重键比对 | A7 |
| ④ 粗筛 | 固定输出 `{is_candidate, relevance, confidence, reason}`,相关度阈值双重把关 | D1、scope 范围说明 |
| ⑤ 抽取 + 断言守卫 | 平台通用硬规则(不臆造/未披露用 status/附原文片段/日期精度)+ Schema 校验;三态守卫按语境词降级、隔离、待人工 | D2、D4、D3、K 抽取模式 |
| ⑥ 建草稿 | 记录号、反规范化查询列、record_type 推断、来源兜底、可信度按主体重定级、embedding | A2、A3、A5、A9、A11 |
| ⑦ 复核发布 | 状态机 extracted→first→[second]→published;含"确认"断言即双签;发布红线校验 | C2、D5、A10 |

## 5. 读取方式与显式 null

> 本章说明两类键在契约层的读取方式,消费者不感知差异。

- **经 DEFAULTS 合并**(缺省即中性行为;画像写 `null` 且键在 `_EXPLICIT_NULL_KEYS` 内表示"关闭",如 `reports_engine.amount_sum: null`):
  record / dictionaries.relevance_term_fields / coverage / sources(除下列)/ quality / update.followup_* / outputs / ui / demo / mock / scope / keywords / pipeline。
- **原样读取**(没有平台缺省、缺失即"无"):`need.*`、`compliance.*`、`record_schemas[]`、`entity_links`、`dictionaries.file / discovery_terms_file`、
  `sources.seed_file / reputation_registry / repost_detection / credibility_levels`、`update.lagged_fields / watch_kinds / expansion_rules / burst_signals / close_condition`、
  `outputs.reports / alerts / kpi`、`quality.model / double_review_fields`、`benchmark.*`。这些多为说明性或校验用键。
- **任务模式下的 null**:参数库合并时 `null` 不覆盖已有值(01 §4.2);想在 overrides 里"关闭"某报表,直接写 `amount_sum: null` 即可(合并后的值就是 null,再由契约层按显式 null 处理)。
