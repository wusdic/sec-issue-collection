## T. 任务与参数库(平台的运行单位)

> 本组是平台的入口:一切从"新建一个任务"开始。任务规定采集什么、多久一次、用什么参数;参数库让共性参数一次沉淀、处处复用。

**T1 · 新建任务**(参数)
- 作用:用一份十几行的任务文件规定这个任务要干的事——目标、状态、节奏、预算、引用哪些参数库条目、本任务特有的覆盖。
- 给谁用:需求负责人。
- 入口:复制 `config/tasks/task.template.yaml` 为 `config/tasks/<id>.yaml`。
- 输入 → 输出:task 元信息 + `use` + `overrides` → 一个可编译的任务。
- 参数:`task.*`(02 §2)、`use`、`overrides`(与画像同构)。
- 用法要点:先用现成条目拼(地域 + 行业 + 记录形态 + 可信度 + 节奏 + 输出),只写粗筛目标、合规与对标;范围值都给同义词;先轻量记录形态再上 Schema。
- 注意:列表合并是追加去重,想"替换"就不要引用含那段列表的条目;引用不存在的条目直接报错。
- 验证:`test_task_mode`。

**T2 · 编译 / 装载 / 状态管理**(通用)
- 作用:任务编译成画像(引擎契约)并装载进库;用状态控制自动化是否执行。
- 给谁用:需求负责人(看编译结果)、管理员(装载、暂停/恢复)。
- 入口:`GET /tasks`、`GET /tasks/{id}/compile`、`POST /tasks/{id}/setup`、`PUT /tasks/{id}/status`;CLI `task-compile` / `task-setup`;`cli init --need <id>` 自动识别任务文件。
- 输入 → 输出:任务文件 → 编译后画像(含 `task`、`compiled_from`)→ NeedProfile + 词表 + 关键词自动生成 + 种子源。
- 参数:`task.status`(draft / active / paused / finished)、`task.schedule.mode / start / end`。
- 用法要点:装载前先 `task-compile` 看一眼合并结果;暂停用状态不删任务,数据与资料库都保留;campaign 任务填 start/end,过期自动不跑。
- 验证:`test_task_mode::test_setup_task_registers_and_runs_pipeline`、`test_is_runnable_respects_window`。

**T3 · 参数库浏览与提炼**(通用)
- 作用:把任务里验证有效的一段参数存成可复用条目;查看每个条目被哪些任务引用。
- 给谁用:运营、需求负责人;开发者补平台级条目。
- 入口:`GET /library?kind=&tag=`、`GET /library/{id}`、`POST /library/extract`;CLI `library-list` / `library-extract <任务> <点路径> <新id> <kind> <名称>`。
- 输入 → 输出:任务 id + 点路径 → `config/library/<kind>/<id>.yaml`(带 provenance)。
- 用法要点:提炼标准见 01 §3.3(至少两个任务会用 / 与领域有关且稳定 / 维护成本高);改条目前用 `library-list` 看 `used_by`;条目改动就是新版本(git)。
- 验证:`test_task_mode::test_extract_preset_roundtrip`、`test_library_lists_presets_with_usage`。

**T4 · 任务切换与界面定义**(通用)
- 作用:头部切换当前任务;页签/列/筛选/详情/仪表盘/日报文案全部按该任务的画像渲染。
- 入口:`GET /needs`(含未装载的任务文件)、`GET /needs/{id}/ui`。
- 用法要点:界面只认角色与定义,换任务不换界面;`/needs` 里 `registered=false` 的任务是"文件有了还没装载"。
- 验证:`test_task_mode::test_list_needs_includes_task_files`、`test_platform_generalization::test_needs_api_and_ui`。

## A. 找得快(信息一公开尽快进库)

> 本组决定"多快能拿到":任务节奏反推抓取间隔,官方接口直采,搜索引擎与平台号补充,早停与时效窗控制成本。

**A1 · 分级抓取调度**(通用)
- 作用:按源等级(A/B/C)与任务节奏(cadence → 时效 SLA)反推抓取间隔,重要源抓得勤、次要源抓得省。
- 给谁用:自动化;运营调等级。
- 入口:自动(`daily` 每日采集 / `scheduler.due_sources`,只取 active 且在有效期的任务);数据源页调 tier。
- 输入 → 输出:源等级 + SLA → 到期源清单 → 采集任务。
- 参数:`task.schedule.cadence`、源 `tier`、设置 `daily_auto_hour / daily_auto_limit_sources`。
- 用法要点:把官方通报栏目、监管处罚栏目设为 A 级;cadence 写 hourly 只对真正需要小时级的任务,否则白耗配额。
- 注意:半自动源与自动发现的子栏目不独立调度。

**A2 · 官方 JSON 列表接口直采 `json_api`**(通用;配置参数;GET/POST/表单)
- 作用:政务站/监管站的 JSON 列表接口零代码接入,比解析 HTML 列表快且稳。
- 给谁用:运营(配源);自动化。
- 入口:种子源文件 / 数据源页新增源,`adapter: json_api`。
- 输入 → 输出:`api_url/params/page_param/items_path/fields` → 条目(标题/链接/日期/发布者)。
- 用法要点:先用浏览器开发者工具看接口返回,填 `items_path` 与字段路径;`max_pages` 控制回查深度;有 channel code 的站一个 code 一个源;接口要求 POST 时填 `method: POST`。
- 验证:`test_borrowed_features::test_json_api_adapter_pages_and_maps_fields`、`test_mainline_closure::test_json_api_post_uses_post_json`。

**A3 · 搜索引擎定题检索**(通用;词表参数)
- 作用:用关键词矩阵每日到搜索引擎/公众号搜索捞新内容,补官方栏目之外的披露。
- 入口:查询型源(baidu_search / bing_rss / sogou_wechat / so360 / ddg)+ 关键词矩阵。
- 参数:`keywords.*`、`task.schedule.time_filters`、`task.budget.*`、设置 `prospect_engines`。
- 用法要点:先跑"找源路径自检"确认引擎可用;时间过滤开"近 7 天";预算按引擎反爬能力放,宁可多源少词。
- 注意:引擎连错达阈值本轮熔断,下轮再试。

**A4 · 公众号 / 平台号通道**(通用)
- 作用:公众号文章、百家号、微博号当作"号"而不是"站"识别与采集;搜狗临时链当刻永久化。
- 用法要点:执法通报大多首发公众号,保留 `sogou_wechat` 引擎;公众号候选需初评后再入库。

**A5 · 翻页早停与时效窗口**(通用;参数)
- 作用:列表翻页遇到已采/过旧内容自动停;发布早于时效窗的历史内容只留薄记录用于去重。
- 参数:`task.schedule.time_window_days`(→ `scope.time_window_days`;缺省设置 `collect_recency_days`)。
- 用法要点:招标类窗口 30 天,法规类可放大到 3–5 年(补历史),事件类 1–2 年;节奏套餐条目(`schedule.*`)已带常用组合。

**A6 · 浏览器渲染与反爬降级**(平台常量;设置)
- 作用:JS 注入的页面、验证页用 Playwright 渲染;没装或失败自动降级 httpx。
- 参数:设置 `playwright_enabled`、并发上限、`fetch_timeout`、`crawl_delay_seconds`。
- 用法要点:先不开渲染跑一轮自检,只对确需渲染的引擎/源开;渲染并发按内存封顶。

**A7 · 编码探测**(平台常量)
- 作用:HTTP 头 → HTML meta → 猜测,政务站 GBK/GB2312 页不再乱码。
- 验证:`test_decode_body_handles_meta_gbk`。

**A8 · 采集任务(后台、可查、可取消)**(通用)
- 入口:采集页"开始采集" / `POST /crawl/run` / `GET /crawl/current` / 日志 / 诊断回放;自动:每日。
- 用法要点:切页不丢;看"诊断回放"能知道每篇为什么被筛掉;`limit_sources` 用于试跑。

## B. 找得全(该有的都有)

> 本组决定"漏不漏":从任务的范围限定出发生成关键词、找源、盘点覆盖度,并用对标基准量化漏报。

**B1 · 范围限定 scope**(参数)
- 作用:一处声明地域/行业/主题/主体名单/文种/时间窗,五处消费(关键词、粗筛提示、闸门、覆盖度、找源)。
- 给谁用:需求负责人。
- 参数:`scope.*`、`scope.require_mention`;地域/行业/文种通常 `use` 参数库条目(`scope.region.*` / `scope.industry.*` / `scope.doctypes.*` / `scope.topic.*`)。
- 用法要点:每个值都给同义/简称(`terms` / `aliases`),这是召回的关键;只对"必须提到才算"的维度开 `require_mention`;主题词写"事项级"(互联网诊疗、中标公告)而不是泛词;验证有效的同义词表提炼进库。

**B2 · 关键词自动生成与组合**(通用;配方参数)
- 作用:scope 派生词组 + 静态词组 + 监控名单 → 缺省或自定义配方组合成矩阵,存为生效版本。
- 入口:设置页关键词区"自动生成关键词 / 生成并用模型扩展"、`POST /keywords/generate`、`cli keywords-generate`、装载时自动。
- 参数:`keywords.groups / compose / expand_with_llm / expand_per_term / negative_terms`、`task.schedule.time_filters`。
- 用法要点:先看"展开示例"是否像人会搜的词;主体/地域/行业不要单独搜,配主题/文种/动作;模型扩展后人工抽检一轮再放开;排除词把招聘/培训/课程填上。
- 验证:`test_scenarios::test_keywords_generated_from_scope`、`test_demand_matrix`。

**B3 · 关键词进化(增益/歇息/淘汰/挖词)**(通用)
- 作用:按实际产出给每条词打分,限定词增益 <1 的退出组合,表现差的词歇息,从相关标题挖新词。
- 入口:自动运维"queries";`GET /query-evolution`、`POST /query-evolution/run`。
- 参数:设置 `term_weak_lift / term_min_samples / query_*`。
- 用法要点:让它跑够 3–4 轮再看结论;"锚点单独跑"是增益分母,别手动删掉。

**B4 · 六通道源发现 + 候选评分 + 自动 trial**(通用;权重参数)
- 作用:引文、转载、公众号引用、搜索命中、关联扩展等证据累积 → 候选评分 → 达阈值自动入库试运行。
- 入口:自动(采集伴生 + 自动运维"candidates");数据源页候选池(收下/拉黑)。
- 参数:`sources.discovery_scoring`、设置 `discovery_auto_trial_threshold`。
- 用法要点:阈值先高后低;候选池每周看一次,拉黑明显无关的,系统会记住。

**B5 · 主动找源 + 覆盖空白词 + -site 排除 + 切题率闸门**(通用)
- 作用:拿找源词去搜索引擎捞新渠道;覆盖空白的维度自动生成方向词;霸榜的已有域自动排除;引擎跑题自动判不可用。
- 入口:数据源页"主动找源"、自动运维"prospect"、`POST /sources/prospect`。
- 用法要点:先自检引擎;看"找源完成"结论里的丢弃原因,若全是"已有源"就该换更细的词或引擎。

**B6 · 引擎自检与自动调优**(通用)
- 作用:整池测一遍,可用的写进引擎列表;后台跑、结果落库、切页可见。
- 入口:数据源页"找源路径自检"、首次流程 engines、自动运维"engines"。
- 参数:`sources.prospect.selftest_query`(缺省找源词第一条)。
- 用法要点:自检词要"该任务一搜必有结果"的词。

**B7 · 根域源栏目定位**(通用;提示词参数)
- 作用:只填了网站根地址的源,自动识别相关栏目并验证后作为子源采集。
- 参数:`sources.column_discovery.hint_words / path_hints`、设置 `column_*`。
- 用法要点:提示词写栏目名常见词而非内容词;定位一次后 TTL 内复用。

**B8 · 覆盖度盘点(缺哪块找哪块)**(通用;维度参数)
- 作用:按覆盖维度看近 N 天哪些取值没记录,空白直接翻译成找源词。
- 入口:数据源页覆盖度、`GET /coverage`、能力 `coverage.summary`。
- 参数:`coverage.*`,无词表时取 scope(`coverage.scope_kind`)。
- 用法要点:窗口与门槛按任务节奏定(日报型 30 天,法规型 90 天)。

**B9 · 监控名单 WatchTarget**(通用)
- 作用:运行中追加企业/主题/地域监控对象,自动并入关键词。
- 入口:`POST /watch-targets`。
- 用法要点:填别名;到期日到了自动失效;稳定的名单应提炼成 `scope.*` 条目。

**B10 · 对标基准与漏报率**(通用)
- 作用:上传一份权威汇总/人工抽样清单,算库里的召回;漏报归因为 doc_only(采到没成记录)与 not_found(没采到)。最近一次召回以 0.5 权重进评分卡"完整性"。
- 给谁用:分析员、需求负责人。
- 入口:`POST /benchmark`、`GET /benchmark`、能力 `benchmark.run`。
- 参数:`benchmark.baselines / target_recall`(任务特有)。
- 用法要点:每月拿官方月报/协会汇总做一次;not_found 多 → 找源与关键词,doc_only 多 → 粗筛规则与去重键。
- 验证:`test_mainline_closure::test_benchmark_recall_and_scorecard_blend`。

## C. 真实可信(每条都说得清从哪来、可不可信)

> 本组决定"信不信得过":来源分级与主体信誉定可信度,验证阶段与三态守卫防止臆造,复核红线与追溯闸门守住发布。

**C1 · 来源可信度分级与确认授权**(参数)
- 作用:S1–S4 分级;只有 `confirm_allowed` 等级的来源才能支撑"已确认"断言。
- 参数:`sources.credibility_levels`;参数库条目 `quality.official_only`(S1)、`quality.official_first_policy`(政策类)。
- 用法要点:法规类只放官方(S1);事件类 S1+S2。

**C2 · 发布主体信誉名录 + 转载溯源**(参数)
- 作用:按发布主体(公众号/机关)定级;识别转载并追原始出处。
- 参数:`sources.reputation_registry / repost_detection`。

**C3 · 真实性验证 verify**(通用;参数)
- 作用:官方域可信度 / 正文哈希 / 标题一致 / 密级标记 → verified / unverified / pending_review;含密级标记的只登记不入库正文。
- 入口:缺省流水线阶段;能力 `verify`;文档列表徽标。
- 参数:`sources.verification.*`、`sources.grading.official_domains`。
- 用法要点:把本任务的权威非 .gov.cn 域(交易所、行业协会)填进官方域名录。
- 验证:`test_verify_text_levels_and_sensitive`、`test_documents_api_exposes_verification`。

**C4 · 断言三态守卫**(参数)
- 作用:关键断言分 声称/估算/确认,语境不符自动降级,隔离字段不得混入,模型给的"确认"一律待人工。
- 参数:`quality.assertions.*`;参数库条目 `quality.tristate_money_cn`。
- 用法要点:只对真正需要"确认"语义的金额/数量字段开三态;语境词按行业补。

**C5 · 复核双签与发布红线**(通用;参数)
- 作用:含确认断言的记录必须双人复核;发布时严格 Schema 校验 + 来源等级校验。
- 入口:复核台;`POST /review/{id}/approve|reject`。
- 用法要点:复核员先看三态字段与来源等级;红线拦下的不要硬发,补来源或降级。

**C6 · 可追溯校验(报表闸门)**(通用)
- 作用:任何"已确认"断言必须挂允许等级来源,否则报表拒绝出数。
- 入口:仪表盘"断言可追溯"、`kpi.traceability_check`。

**C7 · 再核查内容变化**(通用)
- 作用:到期回访记录的来源页重抓比对哈希,内容变了写进回访任务并记"重要"动作。
- 入口:自动运维任务 `recheck`;能力 `followup.recheck` / `verify.recheck`。
- 用法要点:回访台看到"[内容已变化]"前缀就先核对状态(生效/废止/修订),再补字段。
- 验证:`test_mainline_closure::test_recheck_due_flags_changed_sources`。

**C8 · 当刻存档(原文/图片/附件/截图 + manifest 哈希 + 抽检)**(通用)
- 入口:采集伴生;`cli verify-archives`;`GET /archives/{id}`。
- 用法要点:首发全量、转载薄存;每月抽检。

## D. 好用可用(结构化、干净、无重复)

> 本组决定"能不能直接用":粗筛与抽取产出结构化记录,闸门与去重保证干净,回访与关系谱系让记录随时间保持可用。

**D1 · 粗筛(相关度双阈值)**(提示词参数)
- 作用:模型判是否属于本任务,相关度≥keep 入选、manual 区间待人工、其余淘汰。
- 参数:`quality.screen.*`(任务特有)、设置 `screen_keep_threshold / screen_manual_threshold`、可选小模型。
- 用法要点:`include_rules/exclude_rules` 写成"情形"而不是关键词;粗筛用便宜模型。

**D2 · 结构化抽取(Schema / 轻量)**(参数)
- 作用:按记录 Schema 抽取,平台硬规则 + 任务规则;轻量模式按角色生成 Schema。
- 参数:`record_schemas`、`pipeline.extract_mode / light_fields`、`quality.extract_rules`;记录形态条目 `record.*` 已包含 Schema 与角色。
- 用法要点:先用 `record.light_document` 跑通再上完整 Schema;规则只写"模型会犯的错";Schema 里 required 就是完备度缺省权重。

**D3 · 范畴闸门**(参数)
- 作用:粗筛漏网的兜底:record_type=范畴外、排除正则、必须提及维度。
- 参数:`quality.scope_guard`、`scope.require_mention`。

**D4 · 三层去重(URL / 同稿簇 / 记录指纹)+ 语义召回**(通用;键参数)
- 参数:`record.dedup.*`(在记录形态条目里)、设置 `simhash_hamming_max / fingerprint_window_days / semantic_recall_threshold`。
- 用法要点:去重键优先唯一编号(信用代码/文号/项目编号);文档型窗口放大;指纹命中转人工合并而不是静默丢。

**D5 · 记录类型三值与汇总型分流**(参数)
- 作用:单一记录 / 汇总情报(通报、盘点)/ 范畴外;汇总型单独统计不污染主体维度。
- 参数:`record.record_types`。

**D6 · 完备度评分**(参数)
- 参数:`record.completeness_weights`。
- 用法要点:决策字段权重高;"未披露"也给过程分。

**D7 · 人工待定队列(重跑 / 并入 / 不相干)**(通用)
- 入口:采集页文档列表 `POST /documents/{id}/resolve`。

**D8 · 回访补全(T+N 触发)+ 一键检索包**(参数)
- 参数:`update.followup_schedule / followup_triggers / followup_search`。
- 用法要点:触发器只盯"会滞后落地"的字段(罚款、判决、生效日、中标人);检索包链接指向权威库;观测型任务 `followup_schedule: []`。

**D9 · 记录关系谱系(废止/替代/修订/依据)**(通用;规则参数)
- 入口:可选阶段 `relations`、能力 `relations.extract`、`GET /events/{id}/relations`。
- 参数:`quality.relations.patterns`、`pipeline.stages`。
- 用法要点:法规/标准类任务把 `relations` 阶段放在 draft 前。

**D10 · 记录列表 / 详情 / 筛选(角色驱动)**(界面参数)
- 参数:`ui.*`(通常在记录形态条目里)。
- 用法要点:列表只放决策要看的 6–8 列;详情分区按"先结论后证据"排。

## F. 组件(可插拔,不属主线)

> 本组的功能都有明确插件点,任务按需启用;新增渠道或目标只登记一个函数。

**F1 · 通知组件 `notify`**:渠道注册表 email / feishu / webhook(钉钉、企微、自建);`outputs.notify.channels`(条目 `outputs.notify.all_configured`);能力 `notify.send`。用法:日报、告警、自定义能力都走它;新渠道登记一个函数。
**F2 · 日报 `digest`**:按任务分组/排序/标题;页面看、下载、按渠道推。参数 `outputs.digest`。
**F3 · 线索引擎 `leads`**:记录 → 产品映射 → 窗口期 → 评分 → 话术;`leads_engine.enabled` 整体开关(首个实例专用,其它任务默认关);话术只引用公开事实、不贬损任何主体。
**F4 · 报表内核 `kpi`**:交叉表 / 金额汇总(三态或数值)/ 状态计数 / 缺字段清单 / 质量评分卡;口径由 `outputs.reports_engine` 声明。
**F5 · 飞书多维表格导出**:`outputs.exports[].kind: feishu_bitable`,按记录号幂等。
**F6 · 动作台账**:系统自动做过的事分级记录,需人确认的高亮;紧急级动作即时走通知组件(只用已配置渠道)。

## G. 平台与运维

> 本组让平台自己转起来:装载、首次部署、自动运维、体检、能力调用、设置、诊断、审计、守护测试。

**G1 · 装载 / 切换 / 界面定义**:`cli init --need|--all`(含任务文件)、`POST /needs/{id}/setup`、`GET /needs`、`GET /needs/{id}/ui`、头部任务切换器;没有画像文件但有任务文件时自动走任务编译(T2)。
**G2 · 首次部署流程(8 步)**:仪表盘/数据源页"首次模式";precheck → seeds → engines → dedup → locate → health → crawl → prospect;前置检查不过直接拒绝并说明。
**G3 · 自动运维(11 任务,各有周期,时间预算)**:seeds / engines / dedup / locate / health / queries / prospect / grade / candidates / recheck / exports;`autopilot_*_days` 设置;只对可跑任务执行。
**G4 · 源体检 / 复检自愈 / 转站内检索 / 试运行定级**:数据源页;停用源到期复检,能出数据自动恢复。
**G5 · 能力注册表**:`GET /capabilities`、`POST /capabilities/{name}/run`、`cli cap-list / cap-run`——任何能力单跑,调试与外部集成的统一入口;"独立程序"用法:`python -m app.cli cap-run extract --need tender_watch --params '{"title":"…","text":"…"}'`。
**G6 · 设置页(运行时参数,改即生效)**:LLM、采集、去重、存档、找源与覆盖、自动化、推送、平台(默认任务);缺省值按"尽量不用改"选定。
**G7 · 诊断留痕与回放**:每篇文档每步决策与模型调用可回放下载。
**G8 · 审计与角色**:admin / analyst / editor / reviewer / readonly;设置、发布、任务装载等动作进审计日志。
**G9 · 质量守护测试**:引擎零行业字面量、分层不向上依赖、跨任务生成式验证、任务编译等价——升级任何模块前必跑。
