# 通用数据采集平台 · 模块边界与升级规范(v1.2)

> 目标:改一个功能、升一个模块,不影响其它模块。手段:分层、只向下依赖、能力层不成环、
> 所有模块只通过 `NeedContext` 取参、注册表式扩展点,并用测试守住这些约束(`tests/test_module_boundaries.py`)。

## 1. 分层与依赖方向

```
L2 编排(可依赖任何下层)      pipeline  prospect  scheduler  crawl_runner  locate  autopilot  bootstrap  daily  profiles  capabilities
L1 能力模块(只依赖 L0;同层可用公开函数,不成环)
     采集:adapters columns health wechat      处理:extraction money_guard dedup events review verify relations exports
     关键词/找源:keywords discovery grading query_evolution      更新/输出:followup leads kpi digest coverage
L0 契约与底座(不依赖上层)   need_ctx prompts llm fetcher archive url_tools simhash reputation settings_service actions notify diagnostics errors
接口层 app/api、CLI、前端      只调用 L1/L2 的公开函数;服务层永远不引用接口层
```

规则(有测试):
1. 任一模块只能 import 同层或更低层;**函数内的延迟 import 也算依赖**。
2. L1 内部无环(用 DFS 检查)。
3. `app/services` 不得 import `app.api`。
4. 契约层(`need_ctx`/`prompts`/`url_tools`/`notify`)只依赖底座。
5. 引擎代码不得出现行业字面量(另一守护测试)。

## 3. 扩展点(加功能不改别人)

| 扩展点 | 怎么加 | 谁会自动看到 |
|---|---|---|
| 新源适配器 | `adapters.py` 新类,`name` 唯一,注册进 `_REGISTRY` | 种子源、找源、体检、试抓 |
| 新处理阶段 | `pipeline.py` 写 `_stage_x(db, need, ctx, doc, st, result) -> bool` 并登记进 `STAGES` | 画像 `pipeline.stages` 写上名字即可 |
| 新能力 | `capabilities.py` 用 `@register(name, group, doc, params)` 登记 | `GET /capabilities`、`cap-run`、前端 |
| 新报表内核 | `kpi.py` 新函数 + `reports_engine` 新键 + `capabilities` 登记 | 画像声明即启用 |
| 新画像维度 | `need_ctx.DEFAULTS` 加中性缺省 + 属性;文档 02 登记 | 老画像不写照常跑 |
| 新回访触发方式 | `followup._trigger_hit` 加一个 `when` 分支 | 画像 `followup_triggers` |
| 新自动运维任务 | `autopilot.TASKS` 加一项 | 首次流程/每日调度 |

## 4. 升级一个模块的操作规范

1. **先看契约**:只改模块内部实现,不改公开函数签名;要改签名就加参数带缺省值(例:`ctx=None`)。
2. **只加不改画像键**:新参数进 `DEFAULTS` 给中性缺省;旧画像不改也能跑(02 的"增量升级"原则)。
3. **跑三道守护**:`pytest tests/test_module_boundaries.py tests/test_platform_generalization.py tests/test_demand_matrix.py`
   —— 依赖方向、行业字面量、跨需求行为三样都没变才算安全。
4. **再跑全量**:`pytest -q`(≈40s)。
5. **独立验证一个能力**:`python -m app.cli cap-run <name> --need <id> --params '{...}'`,不必起整条流水线。
6. 只动前端:前端只认 `/needs/{id}/ui` 与角色键,不认行业字段,后端字段变了前端不用改。

| 原耦合 | 处理 |
|---|---|
| `health → app.api.routes.test_fetch_source` | 试抓逻辑下沉为 `health.probe_source`,接口层只包一层 |

| `query_evolution ↔ prospect` 互相引用 | `query_evolution` 改读 `keywords.recipes_for` |
