## 1. 同类项目借鉴评估

> 本章评估 `wusdic/data-collector`(法规监控 + 资料收集)、`wusdic/caijifagui`(法规查漏补缺方法论,纯文档)、
> `wusdic/data-compliance-platform`(合规清单平台起步包)。结论:三者的"配置驱动多层级法规采集"思路与本平台同源;
> 本平台在源发现、去重、三态守卫、复核发布、回访、线索、多任务隔离上已更完整;值得吸收的是几项具体能力与一套质量方法论。

### 1.1 项目一览

| 项目 | 定位 | 核心资产 | 与本平台的关系 |
|---|---|---|---|
| data-collector | 数据安全法规 7 层+2 库监控;资料搜索/下载/分类;飞书为存储与通知 | 配置驱动爬虫引擎(registry + levels/*.yaml,json_api/html/spa 四种爬法)、探索 Agent、真实性验证、义务条款抽取、适用性匹配、引用关系图谱、增量比对、本地版本备份、三模式调度、飞书多维表/Webhook | 单一领域的深度实现;本平台是多任务通用底座。它的"引擎不认层级只认配置"= 我们的"引擎零行业字面量只认画像" |
| caijifagui | 法规"查漏补缺"任务的方法论 | 7 层+2 库层级定义与判定规则、并行分组补全策略、四维质量评分(完整性 40/准确性 30/一致性 20/时效性 10,A–D)、格式标准、录入规范 | 过程知识,可直接转成评分卡与任务样板 |
| data-compliance-platform | 合规清单产品起步包 | PG Schema(regulations/provisions/enforcement_cases/checklists,含 version_hash、parent_id、obligation_type)、6 官方源 Playwright 爬虫、哈希去重同步器 | 下游产品形态;条款/清单/租户不在本平台范围,但"版本哈希 + 谱系"值得借 |

### 1.3 记入路线图(有价值,但属于下游产品或需真实模型验证)

| 借鉴点 | 来源 | 为什么不现在做 | 平台里的落点 |
|---|---|---|---|
| 义务条款抽取 → 条款级子记录 | data-collector `obligation_extractor`、compliance-platform `provisions` | 是"一条记录派生 N 条子记录"的二次抽取,需要子 Schema 与 UI | `pipeline.stages` 新阶段 `derive` + 子记录 Schema(记录形态条目可带) |
| 适用性匹配(单位画像 × 义务) | data-collector `applicability_matcher` | 与线索引擎同构;等义务抽取落地后复用 `leads_engine.match_dims` | `outputs.match_engine`(线索引擎泛化) |
| 层级体系 7 层+2 库作为法规类任务样板 | caijifagui、data-collector `levels/*.yaml` | 已可用 `grade_order`+`doc_types`+`coverage` 表达;做成参数库条目 `record.regulation_library` 需要一轮真实源验证 | 参数库条目 |
| 探索 Agent 的"线索 → 触发补爬" | data-collector `discovery_agent` | 找源 + 候选评分 + 自动 trial 已覆盖;多出的"立法动态线索直接触发定向抓取"可作自动运维任务 | `autopilot.TASKS` |

### 1.4 明确不采用

- 飞书多维表格作为**主存储**:本平台以数据库为主存储、飞书为导出面,否则去重/复核/回访/报表都要绕飞书 API。
- 每个来源一个专用爬虫类:本平台坚持通用适配器 + 配置;站点专用解析只在字段级列表解析确有必要时加。
- 子代理并行补全的组织方式:属于人/Agent 的工作流,不是采集引擎能力;评分与格式标准已吸收。
- 合规清单/租户/订阅:下游产品范畴。

### 1.5 对参数的影响(均有中性缺省)

`sources.verification`(official_domains / official_suffixes / sensitive_markers)、`quality.relations.patterns`、`outputs.exports[]`、`outputs.quality_scorecard.weights`、
`pipeline.stages` 新增可选阶段 `verify`(缺省开)与 `relations`(文档型建议开)。这些键都可放进参数库条目(如记录形态包)供任务复用。

## 2. 路线图

> 本章按主线、任务模式、规模化三条线列出下一步。排期以真实环境校准为前提。

| 线 | P1 | P2 |
|---|---|---|
| 主线加深 | 真实模型校准(关键词扩展质量、切题率、候选阈值);条款级二次抽取(`derive` 阶段);关系可视化;时间序列报表;对象型 diff/追加语义;告警型输出 `outputs.alerts` | pgvector 语义召回;多副本部署 |
| 任务模式加深 | 参数库页面化(浏览/提炼/引用图);库变更影响面提示与一键重编译;任务级运行时设置覆盖(并发/阈值按任务);画像/任务 JSON Schema 校验;更多平台级条目(`keywords.*` 动作词组、`sources.*` 行业源包、法规类记录形态) | 任务模板市场(招标情报/舆情/竞品等成套条目);任务级配额与调度优先级仲裁 |
| 规模化 | 多任务并发调度 | 告警/订阅输出;跨任务争用仲裁 |
| 合规 | `compliance.personal_info=true` 时强制最小化字段与审计 | — |
